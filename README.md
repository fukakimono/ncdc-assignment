# NCDC フロントエンド課題

React + TypeScriptで実装。開発環境にはViteを使っている。

## 起動方法

Node.js 22.12以上が必要。

```bash
npm ci
npm run dev
```

ターミナルに表示されたURLを開く。

## 確認用コマンド

```bash
npm run build         # 型チェック・ビルド
npm run lint          # 静的解析
npm run format:check  # フォーマット確認
```

整形する場合は`npm run format`。テストは未実装。

## 素材

提供されたアイコンを`src/assets/img/icon/`に置いている。importには`@assets`を使える。

Noto Sans JPはGoogle Fontsから読み込んでいる。

## バックエンドの起動

[ncdcdev/recruit-frontend](https://github.com/ncdcdev/recruit-frontend)を別途cloneして、そちらで実行する。

```bash
npm ci
npm run migration:run
npm run build
npm run start
```

接続先は`http://localhost:3000/content`。`src/features/content/api.ts`に定義している。
API仕様は起動後の[Swagger](http://localhost:3000/api)で確認できる。

## 実装について

ページ関連の型・API・コンポーネントは`src/features/content/`にまとめた。API通信は`api.ts`に分け、`App.tsx`で取得結果を管理している。

画面遷移がないのでRouterは使っていない。

タイトルがnullか空文字のページは「無題」と表示する。

作成・更新の引数はバックエンドのDTOに合わせ、`title`と`body`を省略可能にしている。作成時の初期値は呼び出し側で渡す。

ページを選ぶと詳細を取得する。取得中は連続して選択できないよう、一覧のボタンを無効にしている。
本文は改行をそのまま表示する。

作成時はタイトルと本文を空にする。案内文が保存されないよう、「タイトルを入力」と「ここに本文を入力してください。」は編集欄のプレースホルダーにした。作成後はそのページを選択する。

連打によってページが複数作られるのを防ぐため、作成APIの応答を待つ間はボタンを無効にする。

誤って削除しないよう、削除前に確認ダイアログを出す。選択中のページを削除した場合は、選択を解除する。

タイトルは前後の空白も文字数に含め、入力した内容をそのまま保存する。空白だけの入力は受け付けない。1〜50文字の条件を満たすまでSaveを無効にする。文字数の制限が分かるよう、編集中は入力欄の下に`文字数/50`を表示する。入力は`maxLength`で50文字までに制限し、表示は空白も含めて数える。保存に失敗した場合は、入力を残して再試行できるようにした。

Cancelでは変更を破棄する。別のページや新規作成したページに移った場合も、未保存の変更を破棄して編集を終了する。保存中はページが切り替わらないよう、サイドバーの操作を無効にする。

本文も空白・改行を含めて数え、そのまま保存する。空白・改行だけの入力は受け付けない。編集中は`文字数/2000`を表示し、10〜2000文字の条件を満たすまでSaveを無効にする。入力欄の上限とは別に、保存時にも文字数を確認する。
